# Bili 开屏助手

原生 Android / Kotlin 小工具，使用用户主动授权的无障碍服务，自动点击哔哩哔哩开屏中的可访问“跳过”按钮。不是广告拦截器，不修改 Bilibili，不保证广告不展示。仅适配国内官方版 `tv.danmaku.bili`。

## 构建

- JDK 21、Android SDK Platform 35、Build Tools 36.0.0。
- Android Gradle Plugin 9.1.0（内置 Kotlin）、Gradle 9.3.1。
- 将 SDK 路径填入本机 `local.properties` 的 `sdk.dir`，或设置 `ANDROID_HOME`。
- Windows：`./gradlew.bat testDebugUnitTest assembleDebug`。
- APK：`app/build/outputs/apk/debug/app-debug.apk`（调试签名，仅用于本地测试）。

## 使用

1. 安装 APK（Android 8.0 及以上）。
2. 打开应用，启用开关并同意说明。
3. 在系统无障碍设置中启用本工具。部分系统对侧载应用限制无障碍授权，请自行确认来源后根据系统提示操作。
4. 从桌面打开哔哩哔哩，验证开屏是否自动跳过。
5. 关闭开关可立即停止后续自动点击；要撤销权限，在系统无障碍设置中停用服务。

## 检测规则与限制

- 根据实际活动窗口识别目标包；从其他窗口进入目标应用后，最多检测 8 秒。
- 每 200 毫秒最多检查一次，每次会话最多成功点击一次，最多遍历 500 个节点。
- 只点击右上或右下方、小尺寸、可见可用、文字严格匹配“跳过”及倒计时变体的节点。
- 文字本身不可点击时，最多向上查找两层父控件，父控件仍必须同包名、包含文字且满足相同的小尺寸及位置限制，绝不点击大型广告容器。
- 不使用固定坐标或手势。不可访问的广告可能完全无法识别。
- 窗口变化不等于真实冷启动：通知栏、系统弹窗等可能重开检测窗口。无法从通用无障碍事件可靠判断开屏广告，仍有误触风险。
- 系统接受点击不等于已成功关闭广告，计数仅表示点击 API 返回成功。
- 不保证兼容所有 Bilibili/Android 版本；发布前需要真实设备测试。

## 隐私

不申请网络、存储、悬浮窗权限，不截图，不上传或保存界面内容。为判断前台切换监听窗口事件，但只遍历目标应用的节点。仅本地保存开关、点击次数和最后点击时间，支持清空记录，关闭系统备份。

## 手动验收清单

- 首次安装默认关闭，取消同意后保持关闭。
- 未授权、授权、撤销授权时主页显示正确状态。
- 非 Bilibili 前台、首页、视频页不得误点。
- 开屏有合规的“跳过”控件时点击一次；无按钮时不操作。
- 等待 8 秒后，同一前台会话不再点击。
- 关闭开关、锁屏、切换应用、拉通知栏后验证行为。
- 无障碍节点不暴露按钮时，确认工具安全地不操作。
